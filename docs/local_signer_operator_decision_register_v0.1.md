# Local Signer Operator Decision Register v0.1

Status: `DEFINED_REGISTER_ONLY`

Foundation: 125, workstream 1

Subordinate authority: L28 Protocol v1.0.0

## 1. Purpose and non-activation boundary

This document is the canonical stable-ID register for every `OPERATOR_DECISION_REQUIRED` item defined by Foundation124. It records questions and admissible decision shapes without selecting any production value, provider, mechanism, threshold, count, topology, limit, or authorization.

All 47 decisions remain `OPERATOR_DECISION_REQUIRED`. An unrecorded default, implementation choice, caller value, adapter output, Harness/Evals recommendation, Bitcoin observation, test fixture, or prior operational habit cannot resolve a decision. Missing, partial, contradictory, expired, superseded, or unauthenticated decision evidence fails closed.

This register does not authorize implementation, signer invocation, key or wallet operations, signing, RPC/network access, broadcast, mining, settlement, database work, deployment, testnet, or activation.

## 2. Stable identifier and governance rules

Decision IDs are immutable and never reassigned:

- `LSOD-EVD-NNN`: authenticated evidence decisions;
- `LSOD-CUS-NNN`: custody decisions;
- `LSOD-STA-NNN`: atomic security-state decisions;
- `LSOD-OPS-NNN`: trusted-time, audit, resource, isolation, and assurance decisions;
- `LSOD-GAT-NNN`: blocked Bitcoin or signer-activation gates.

A future resolution must create a separately authorized, versioned decision record that names the accountable approver, exact selected value/profile, rationale, threat model, dependencies, implementation evidence, conformance evidence, independent-review evidence, effective interval, supersession rule, and rollback/change-control rule. Editing this register alone cannot resolve a decision.

Allowed decision shapes below define only the form a later decision may take. They are not recommendations and select nothing. `Approver` identifies the authority class that must be named later; every current approver is unassigned.

Within dependency cells only, abbreviated forms such as `EVD-001`, `CUS-001`, `STA-001`, `OPS-001`, and `GAT-001` are exact aliases for `LSOD-EVD-001`, `LSOD-CUS-001`, `LSOD-STA-001`, `LSOD-OPS-001`, and `LSOD-GAT-001`. Ranges use the same stable namespace and are inclusive; no abbreviated value defines a second identifier.

## 9. Authority, failure, and protocol invariants

Every future decision remains subordinate to L28 Protocol v1.0.0. `coin.tx_validation.validate_transaction` remains the canonical mandatory validator. Authorization is not validation. Eligibility is not signer invocation. Missing required evidence, state, policy, time, audit, custody health, resource controls, decision records, or independent review fails closed.

Harness/Evals remains advisory only. Adapters remain transport only. Bitcoin remains external evidence only and has zero authority over L28 issuance, supply, height, validation, consensus, history, or settlement.

This register preserves exactly: hard cap `28000000`; emission ceiling `11130000`; historically mined `2824584`; treasury locked `500000`; circulating snapshot `2324584`; halving interval `210000`; reward schedule `[28,14,7,3,1,0]`; historical mined-through entry `100877`; next canonical height `100878`; coinbase-only issuance; consensus-derived canonical height; and immutable historical evidence.

Production Bitcoin proof architecture, Bitcoin confirmation/reorg policy and count, observer quorum/independence, and signer implementation/runtime/deployment/activation remain `BLOCKED_REQUIRES_FUTURE_SECURITY_DECISION`.

Foundation125 resolves no decision and grants no implementation or runtime authorization.
